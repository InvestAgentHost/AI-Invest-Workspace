## 一、先建立总图：Nokia 卖的不是一种“网络设备”

### 1.1 三类网络分别搬运什么

理解 Nokia 最容易犯的错误，是把 Optical Networks、IP Networks 和 RAN 都理解成“传数据的盒子”。三者确实都在搬运信息，但工作对象完全不同。

| 网络层 | 直接处理的对象 | 最核心的问题 | Nokia 的主要产品形态 |
|---|---|---|---|
| Optical Networks | 光纤中的波长、光场和承载于光上的比特 | 如何让极高速信号跨更长距离，同时对抗损耗、色散、噪声和光纤非线性 | 相干光引擎、WDM/OTN 设备、ROADM/线路系统、光网络软件 |
| IP Networks | 带地址和业务语义的数据包 | 每个包下一跳去哪、遇到拥塞先发谁、故障时如何快速绕行 | 路由器、数据中心交换机、网络处理器、NOS、控制与安全软件 |
| RAN | 空气中的电磁波以及由其恢复出的无线基带样本 | 多个移动终端如何共享有限频谱，在干扰、衰落和移动中维持连接 | 天线/RRH、Massive MIMO、基带、Cloud/Open RAN、RAN 自动化 |

它们在真实网络里是串联关系，而非相互替代关系。一个手机或 AI 集群发出的数据，可能依次经过无线接入、IP 转发和光传输：

本文优先拆解这三条主线，是因为它们最集中体现 Nokia 面向 AI/Cloud 与运营商网络的底层技术能力。Fixed Networks、Core Software、Technology Standards 等业务仍属于 Nokia 核心组合，但其完整产品边界已在 [产品手册](./Nokia-official-product-handbook-2026-07-25.md)中列出，不在本文重复铺开。

```text
手机 / 传感器
      ↓ 空口：电磁波
天线 + RRH + Massive MIMO
      ↓ 前传：数字化无线样本或功能拆分后的数据
AirScale / Cloud RAN 基带
      ↓ 回传：以太网、IP、MPLS
7730 / 7750 等 IP 路由网络
      ↓ 线路侧：相干波长、WDM
1830 / ICE / FlexILS 光网络
      ↓
核心网、互联网、云或 AI 数据中心
```

AI 数据中心的路径不经过无线空口，但也会跨越多个层级：

```text
GPU / 加速器
  ↓ 电信号
NIC / 前面板光模块
  ↓ 以太网帧
7220 / 7250 IXR leaf-spine fabric
  ↓ IP/Ethernet 流量
7750 SR 数据中心网关
  ↓ 可插拔相干光或独立光传输设备
ICE-X / 1830 GX / 1830 PSS + FlexILS
  ↓ 光纤
另一栋楼、另一园区或另一座城市的数据中心
```

### 1.2 一套网络产品的五层结构

无论光、IP 还是 RAN，都可以用同一套层级理解 Nokia 的产品组合。

1. **物理层器件与芯片**：PSE、Tahoe、ICE 光子引擎，FP5/FPcx 网络处理器，ReefShark 基带 SoC。
2. **设备平台**：1830、7750/7730/72xx、AirScale、RRH 和 Massive MIMO 天线。
3. **设备操作系统**：SR OS、SR Linux，以及无线基带软件。
4. **网络级控制与自动化**：WaveSuite、Transcend、NSP、EDA、MantaRay。
5. **设计、部署与持续运维**：集成、优化、升级、保障和托管服务。

这五层解释了为什么不能只拿一个机框参数评价 Nokia。芯片决定性能上限，设备把芯片变成可靠端口，操作系统把端口变成网络功能，控制器把大量设备变成一张可运营的网，服务则把方案落到客户现网。

## 二、Optical Networks：把电比特变成可以远距离传播的受控光场

### 2.1 第一性任务：为什么不能一直用铜线

电信号在铜互连中传播时会受到电阻损耗、趋肤效应、介质损耗、串扰和电磁兼容约束。速率越高，电信号包含的高频分量越多，可容忍的铜链路距离通常越短，均衡和驱动功耗越高。光纤以光作为载体，带宽高、单位距离损耗低、抗电磁干扰，因此承担数据中心间、城域、骨干和海缆的大容量传输。

但光纤不是“把光射进去就能无限传”。工程上至少要同时处理四类损伤：

| 约束 | 直观理解 | 系统如何处理 |
|---|---|---|
| 衰减 | 光传播越远越弱，连接器、熔接点也带来损耗 | EDFA/其他光放大、合理链路预算、接收灵敏度设计 |
| 色散 | 不同频率或偏振成分到达时间不同，脉冲逐渐摊开并相互重叠 | 相干接收与 DSP 补偿、光纤和线路设计 |
| 噪声 | 放大器自发辐射、接收电路和器件噪声降低信噪比 | 调制/FEC 选择、功率控制、低噪声器件 |
| 非线性 | 光功率过高时，光纤不再近似线性介质，不同波长会相互影响 | 功率优化、波形整形、DSP 算法、线路工程 |

所以光网络的本质不是“更亮”，而是：在给定光纤、距离、波长资源、功耗和误码率约束下，把尽可能多的信息稳定地送到远端。

### 2.2 从一个比特到一条相干波长

#### 2.2.1 普通强度调制与相干调制的差别

最简单的光通信可以用“亮/暗”表达信息，接收器只检测光强，这类方式属于强度调制、直接探测（IMDD）的基本思路。相干通信则不仅利用光强，还利用光波的相位，并通常利用两个正交偏振方向。

```text
IMDD：主要问“收到的光有多强？”

相干：同时估计
  - 幅度：光场有多强
  - 相位：波峰波谷处在什么位置
  - 偏振：两个正交方向分别承载了什么
  - 频率偏差：发端与本振激光器是否有偏移
```

这样做能在一个符号中编码更多比特。例如 QPSK 用不同相位状态编码，QAM 同时利用幅度和相位。再叠加双偏振，同一波长的信息密度进一步提高。代价是发射器、激光器、接收光学和 DSP 都更复杂，对信噪比也更敏感。

#### 2.2.2 波特率、比特率和每波长容量不是一回事

波特率描述每秒发送多少个符号；比特率还取决于每个符号包含多少比特、是否使用双偏振，以及 FEC 等开销。概念上可以写成：

```text
毛比特率 ≈ 波特率 × 每符号比特数 × 偏振路数
净业务速率 = 毛比特率 - FEC、成帧及其他开销
```

因此，“135 GBaud”“800G”“1.2T/波长”是不同维度的指标，不能直接混用。更高阶调制可以提高单符号信息量，却需要更好的光信噪比；距离越远，系统往往要在容量和鲁棒性之间回退。Nokia 官网披露 Tahoe 最高 135 GBaud、ICE-X 800 面向 800G，以及 1830 GX 支持 100G-1.2T/波长，这些指标描述的是不同产品层级。[O62][O70][O73]

#### 2.2.3 相干收发链怎样工作

```text
发射端
客户侧以太网/OTN
  ↓ 成帧、FEC、映射
相干 DSP 生成高速数字波形
  ↓ DAC / Driver
激光器 + IQ 调制器 + 偏振复用
  ↓
一条携带幅度、相位和双偏振信息的相干波长

接收端
相干波长 + 本振激光器
  ↓ 光学混频 / 偏振分离
光电探测器 + TIA + ADC
  ↓
DSP：色散补偿、偏振恢复、时钟/载波恢复、均衡、FEC
  ↓
还原客户侧以太网/OTN 数据
```

这里的 DSP 不是普通“转发芯片”。它需要实时求解信道对光波形造成的变化，把已经失真的模拟波形恢复成比特。算法、ADC/DAC、高速 SerDes、封装、激光器与 PIC 必须协同，任何单点不足都可能限制距离、容量或功耗。关于相干 PIC 中激光、调制、探测、偏振与 DSP 的一般原理，可参见本地行业研究 [T2]。

### 2.3 WDM、OTN、ROADM：为什么有了相干模块还需要整套光系统

一条相干波长只解决“如何在一个光载波上装数据”。运营网络还要把许多波长放进同一根光纤，并能在沿途节点增加、取出或转向。

#### WDM：让一根光纤并行承载多条光通道

WDM（波分复用）把不同中心波长的光合并到一根光纤，接收端再分开。它类似多条不同频率的无线电频道共用空气，但介质变成光纤。系统容量因此不只由单波长速率决定，还取决于可用频谱、信道间隔、波长数量及线路性能。

#### OTN：给光传输加上可管理的数字封装

OTN 可把以太网等客户信号映射到标准数字容器，增加开销、监控和 FEC，并进行汇聚与交换。它解决的是“业务怎样被稳定地装进光通道并被运营”，而非光子本身怎样传播。1830 PSS 和 1830 PSS-x 兼具分组、OTN/WDM 或 P-OTN 交换定位，适合需要汇聚、保护和多业务承载的网络。[O61][O65]

#### ROADM：不做光电转换也能改变波长去向

ROADM 使用可重构光学结构，在中间站点按波长选择直通、下路或上路。其核心价值是减少每个节点都进行光-电-光转换的需求，使网络能通过软件远程调整路径。开放线路系统还要包含复用/解复用、放大、功率均衡、线路监测和光层分界。Nokia 的 FlexILS、PSD 与 PSS/PSI-L 位于这一层。[O64]

**官网事实。** 1830 GX 的公开口径为 100G-1.2T/波长、9.6T/架、最高 100T/纤；ICE-X 800 使用 3nm CMOS，官网称 800G 可超过 1,700km；ICE-D 被定位为面向数据中心内部的单片 InP PIC 光互联，官网称连接功耗最高降低 75%。这些均是厂商给定条件下的产品主张，不可直接视为所有链路的实测结果。[O62][O70][O71]

### 2.5 “相干路由”为什么会改变设备边界

传统架构中，路由器输出短距灰光，独立传输设备再把它转换为相干线路波长。可插拔相干光把更多传输功能塞进 QSFP-DD/OSFP 等模块，可以直接插进路由端口：

```text
传统：路由器 → 灰光模块 → 独立转发器/传输机框 → DWDM 线路

相干路由：路由器 → ICE-X 等相干可插拔模块 → 开放 DWDM 线路
```

这能减少设备层级、机房空间和中间电转换，但并不意味着独立光传输设备消失。需要大量客户信号汇聚、复杂 OTN 交换、超长距优化、光层保护或多业务运营时，1830 PSS/GX 等系统仍有价值。真正的边界取决于距离、端口规模、运维模型、故障域和单位比特成本。

### 2.6 Optical Networks 的真正壁垒与验证点

**分析判断。** 光网络护城河不是某一个“最高速率”数字，而是四个闭环：

1. DSP/PIC 能否在目标功耗下实现容量与距离。
2. 光模块能否以高良率完成光、电、热和机械耦合。
3. 线路系统能否管理多波长、多跨段、放大器和 ROADM。
4. 规划软件能否把物理层余量转化为可交付、可维护的业务。

后续研究最应验证：ICE7/PSE-6s 与 ICE-X 的实际客户导入、Infinera 与原 Nokia 产品路线整合、ICE-D 的量产与客户边界、每比特功耗、可插拔与机框式系统的收入替代关系。官网没有提供产品级毛利、BOM、良率或订单拆分。

## 三、IP Networks：让每一个数据包走对路，并在拥塞时维持业务承诺

### 3.1 第一性任务：光纤负责“能到”，IP 负责“去哪”

光网络可以建立一条高速比特管道，却不知道其中哪个数据包属于哪位客户、应去哪个目的地、什么业务更重要。IP 网络读取包头并执行转发策略，承担寻址、路径选择、隔离、拥塞管理、可靠性和安全边界。

一个路由器并不只是许多网口。典型数据路径如下：

```text
入端口收到以太网帧
      ↓
解析包头：MAC、VLAN、IP、MPLS、隧道等
      ↓
查表：目的前缀/标签/业务对应哪个下一跳
      ↓
执行策略：过滤、计量、封装、QoS、遥测
      ↓
通过交换结构送往目标线卡
      ↓
排队、调度、整形
      ↓
出端口发送
```

### 3.2 数据面、控制面和管理面为什么要分开

| 平面 | 做什么 | 时间尺度 | Nokia 对应能力 |
|---|---|---|---|
| 数据面 | 对每个包执行查表、转发、排队和策略 | 纳秒到微秒，线速连续运行 | FP5/FPcx、7750/7730/72xx、IXR |
| 控制面 | 通过 BGP、IS-IS/OSPF、EVPN 等协议学习拓扑和路由，形成转发表 | 毫秒到分钟 | SR OS、SR Linux |
| 管理/自动化面 | 声明意图、生成配置、验证变更、收集遥测、闭环修复 | 秒到长期生命周期 | EDA、NSP、Deepfield |

这一区分很重要。芯片吞吐量高不代表路由协议可靠；操作系统功能多不代表变更不会出错；自动化平台也不能补救底层端口和缓存能力不足。

传统概念中，交换机主要根据 MAC 地址在一个二层网络内转发，路由器主要根据 IP 地址连接不同三层网络。但现代数据中心和运营商设备往往同时支持二层交换、三层路由、EVPN、MPLS 和隧道，因此产品名中的 switch、router 或 interconnect router 已不能单独定义能力边界。研究 7220/7250 IXR 或 7750 SR 时，应看实际芯片、表项、缓存、协议和软件，而不是只看名称。

### 3.3 网络处理器、交换 ASIC、缓存和队列到底在做什么

#### 3.3.1 NPU/ASIC：逐包执行的“流水线工厂”

CPU 很灵活，但难以经济地对数十或数百 Tb/s 流量逐包处理。网络处理器或交换 ASIC 把解析、查表、修改包头、计数和转发做成并行硬件流水线。主要矛盾是：

- **吞吐量**：所有端口同时满载时能否线速处理。
- **可编程性**：新协议、新遥测或安全动作能否通过软件增加。
- **表项规模**：能保存多少路由、MAC、隧道、ACL 和计数器。
- **功耗**：每转发一比特消耗多少能量。
- **确定性**：复杂功能打开后是否仍维持性能与时延边界。

FP5 是 Nokia 面向业务路由的数据面处理器，官网披露 6 Tb/s、约 0.1 W/Gb，并称相对 FP4 节能 75%。FPcx 面向数据中心交换平台。前者更强调丰富业务处理和电信边缘，后者更贴近大规模 leaf-spine fabric；二者不是仅按“谁带宽更大”排列的同一产品。[O31][O39]

#### 3.3.2 缓存、队列和 QoS：端口堵塞时决定谁先走

当多个入端口同时向一个出端口发送，瞬时流量超过出端口能力，就会发生排队。缓存吸收短时突发；队列把不同业务分开；调度器按优先级、公平性或带宽承诺发送；整形和拥塞控制减少持续过载。

缓存不是越大越好。过小会丢包，过大又可能形成长队列和高时延。业务路由器还需处理大量层级 QoS，让一个物理端口同时兑现不同客户、VPN 或应用的 SLA。7730 SXR 公开最多 256K queues，正反映其定位不只是“转发得快”，还要细粒度隔离和调度业务。[O33]

### 3.4 IP/MPLS、Segment Routing、EVPN 各解决什么

- **IP 路由**：根据目的 IP 前缀逐跳选择下一跳，是网络可达性的基础。
- **MPLS**：在包前加标签，便于建立受控路径、VPN、流量工程和快速保护。
- **Segment Routing**：把路径意图编码为一组网络段，减少逐隧道状态并提升可编程性，可运行在 MPLS 或 IPv6 数据面之上。
- **EVPN**：通过 BGP 分发二层/三层可达和多归属信息，常与 VXLAN 或 MPLS 配合，用于数据中心 fabric、运营商以太业务和跨站点连接。

这些协议不是互斥代际。大型运营网络通常在同一设备上按场景组合使用。SR OS 的价值在于把 IP/MPLS、EVPN、QoS、遥测和高可用放进同一电信级 NOS；SR Linux 更强调 Linux 基础、开放模型和数据中心自动化。[O40][O41]

### 3.5 AI 数据中心 leaf-spine fabric 为什么不同于传统企业网

AI 训练把大量加速器组成一个并行系统。某些同步阶段，许多节点会同时向少数节点发送，形成 incast；大流量可能持续占用路径；任何慢链路或丢包都可能拖住整个作业。网络因此强调高双向带宽、低且稳定的尾时延、有效负载均衡、快速故障收敛和深度遥测。

leaf-spine 架构让每台 leaf 连接所有 spine，任意两台 leaf 之间通常只经过固定跳数，并通过 ECMP 使用多条等价路径：

```text
            Spine 1     Spine 2     Spine 3
             / | \       / | \       / | \
            /  |  \     /  |  \     /  |  \
         Leaf A       Leaf B       Leaf C
          / | \        / | \        / | \
       GPU servers   GPU servers   GPU servers
```

它不是靠某台超大核心交换机承载所有流量，而是靠许多并行路径横向扩展。难点也从“单机带宽”扩展为整张 fabric 的路径均衡、配置一致性、拥塞控制和故障处理。

Nokia 的 7220 IXR 公开最高 102.4 Tb/s、支持 1.6TE；7250 IXR 最高 460.8 Tb/s，均面向 AI/云 fabric。数字代表设备容量上限，但客户体验还取决于端口配置、SerDes/光模块、拓扑、拥塞算法和 NOS。[O37][O38]

### 3.6 Nokia IP 产品逐层拆解

| 产品 | 网络位置 | 它解决的核心问题 | 不应混淆的边界 |
|---|---|---|---|
| 7750 SR | 核心、业务边缘、宽带边缘、DC 网关/peering | 超大容量转发，同时执行 VPN、QoS、安全、遥测和业务策略 | 不是单纯 AI 集群 ToR 交换机；最高 230 Tb/s 是平台配置口径 |
| 7730 SXR | 城域汇聚、边缘、移动承载 | 在紧凑平台中提供 1GE-400GE、丰富队列与业务汇聚 | 与 7750 的差别不只是尺寸，更在容量、槽位和部署密度 |
| 7705 SAR | 移动 xHaul、关键行业 | 汇聚传统与分组业务，强调同步、确定性和严苛场景 | 不以 hyperscale fabric 为主战场 |
| 7210 SAS | 接入和汇聚 | 以太/IP/MPLS 业务接入，承接较小节点和企业连接 | 更靠近网络边缘，不等于 7250 IXR |
| 7215 IXS | 数据中心管理/低速接入 | 提供 1G/10G 等紧凑端口 | 不是高带宽 GPU fabric 核心 |
| 7220/7250 IXR | 数据中心 leaf/spine、互联 | 高 radix、高容量以太 fabric 和高速端口演进 | 必须与 SR Linux、光模块和自动化一起评价 |
| FP5 | 业务路由硅 | 在线速下执行可编程业务处理、QoS、安全与遥测 | 不是面向外部市场的独立通用 CPU |
| SR OS / SR Linux | 网络操作系统 | 把硬件资源变成协议、服务、模型和遥测接口 | 两者面向场景和架构不同，不宜简单视为新旧替代 |

产品规格与定位来源见 [O32]-[O41]。

### 3.7 EDA、NSP 和 Deepfield：三种完全不同的软件

#### EDA：让数据中心变更像一笔可验证的事务

EDA 以意图、数字孪生和事件驱动事务管理数据中心 fabric。所谓意图，是让用户声明“网络应达到什么状态”，而非逐台手写命令；数字孪生用于在真实变更前验证预期状态；事务意味着跨多台设备的修改应整体成功或失败，减少半配置状态。Nokia 将其描述为 Kubernetes 微服务并支持多厂商，官网称运营工作量最高降低 40%。这是厂商案例/模型口径。[O42]

#### NSP：跨 IP、光和微波的 WAN 控制与业务编排

NSP 更像广域网络控制器：掌握拓扑、资源和约束，计算路径，开通跨设备业务，并把性能和故障信息用于保障。它覆盖运营商和关键行业 WAN，不等同于专注 AI 数据中心 fabric 的 EDA。Nokia 称 NSP 已部署于全球 1,000+ 运营商。[O43]

#### Deepfield：先识别流量和攻击，再调用网络执行缓解

Deepfield Secure Genome 对互联网端点、前缀、云服务和威胁进行分类；Defender 根据流量异常识别攻击并生成缓解策略；路由器或 7750 DMS 执行丢弃、过滤或清洗。它的系统逻辑是把“看见攻击”和“在网络中阻断攻击”连接起来，而不是把所有流量先牵引到一个外部黑盒。官网披露 Genome 覆盖 5bn+ IPv4/IPv6 地址和 100+ ML 规则，但未披露所有场景的误报率、攻击覆盖率和商业费率。[O44]-[O46]

### 3.8 IP Networks 的真正壁垒与验证点

**分析判断。** IP 设备的壁垒是“硅 + 系统软件 + 长周期可靠性”的乘积。芯片决定容量、功耗和可编程上限；NOS 积累协议、服务和运维行为；客户现网则要求多年无中断升级、故障收敛和跨厂商互通。单一 benchmark 很难代表综合竞争力。

后续研究应验证：7220/7250 在 AI fabric 的客户与份额、FPcx 和光互联的协同、EDA 的多厂商实际覆盖、7750 高速端口放量，以及 Nokia 在 Ethernet AI 网络中相对专用 AI 网络方案的性能、生态和 TCO。

## 四、AI RAN：先理解无线物理层，再判断 AI 到底放在哪里

### 4.1 RAN 的第一性任务：让许多移动终端共享一片不稳定的电磁环境

无线链路与光纤不同。电磁波在空气中传播会因距离衰减，被建筑物遮挡和反射，形成多径；终端移动又引入多普勒变化；相邻小区和用户会彼此干扰；可用频谱还是稀缺且受监管的资源。

RAN 因此要持续解决四个问题：

1. 把数字比特编码、调制成可以经天线发射的无线波形，并在接收端还原。
2. 在时间、频率、空间和功率维度上调度大量用户。
3. 估计不断变化的无线信道，控制波束、编码率和重传。
4. 让终端在小区间移动时保持会话，并把流量送入核心网。

### 4.2 一条无线信号链如何工作

#### 下行：从网络到手机

```text
核心网/IP 回传的数据包
  ↓
基带高层：用户调度、协议处理、重传控制
  ↓
基带物理层：信道编码、调制、层映射、OFDM
  ↓
数字波束赋形 / 多天线权重
  ↓
数模转换、上变频、功率放大（RRH/Radio）
  ↓
天线阵列将射频能量辐射到空间
  ↓
手机天线与基带恢复比特
```

上行则反向进行：天线收到极弱且混有干扰的射频信号，经低噪声放大、下变频和模数转换后，由基带完成信道估计、均衡、解调和译码。

#### OFDM：把难处理的宽带信道拆成许多窄子载波

OFDM 将高速数据分散到许多正交子载波上。每个子载波面对的信道更接近简单平坦衰落，配合循环前缀可降低多径造成的符号间干扰。代价包括峰均功率比高、功放效率受约束，以及对频率同步和相位噪声敏感。

#### MIMO 与波束赋形：不只是“多装几根天线”

MIMO 使用多根发射和接收天线。一种价值是空间复用，即在同一时频资源上传送多层数据；另一种是波束赋形，即控制各天线单元的幅度和相位，使信号在目标方向相干叠加、在其他方向减少泄漏。

```text
若多天线到目标用户的波峰尽量同时到达：目标方向增强
若到干扰方向的相位被设计为部分抵消：干扰方向减弱
```

Massive MIMO 把收发通道数扩大到 32TRX、64TRX 等规模，但性能不只取决于通道数量，还取决于信道估计、校准、波束算法、功放效率、阵列尺寸、散热和站点环境。Nokia 的 Habrok、Osprey 位于这一产品层。[O83]

### 4.3 RRH、基带、RU/DU/CU 分别是什么

| 组件 | 主要任务 | 为什么放在这个位置 | Nokia 产品映射 |
|---|---|---|---|
| 天线/有源天线 | 把导波变成空间电磁波，形成覆盖与波束 | 必须面向真实传播环境 | Habrok、Osprey Massive MIMO、IPAA+ |
| RRH/RU | 射频收发、功率放大、滤波、数模/模数转换及部分低层处理 | 靠近天线可减少高频馈线损耗 | Doksuri、Osprey RRH、Shikra 等 |
| DU | 时延敏感的基带处理、调度和部分物理层/MAC | 需靠近无线站点或边缘，满足实时性 | AirScale 或 Cloud RAN 的分布式功能 |
| CU | 较高层协议、移动性和集中控制 | 可在更集中位置池化和扩展 | AirScale/Cloud RAN 的集中式功能 |
| SMO/管理 | 配置、生命周期、性能保障和 rApps | 需要跨大量站点形成网络级视图 | MantaRay SMO、AutoPilot |

不同 RAN 功能拆分方案会改变 RU、DU、CU 之间传输的数据量、时延和同步要求。把更多低层功能留在 RU，可降低前传压力但减少集中化灵活性；把更多功能集中到 DU/CU，可获得池化和统一升级，却对前传容量、抖动和时延提出更高要求。这是 Cloud/Open RAN 的核心工程权衡之一。

### 4.4 AirScale、ReefShark 和无线软件如何构成基带平台

AirScale Baseband 不是一台普通服务器。它需要在严格实时窗口内处理大量小区和用户的物理层计算、调度、协议与传输。容量卡提供高吞吐计算，控制/传输单元连接无线单元和回传网络，软件定义支持的制式、频段组合和功能。

ReefShark 是 Nokia 自研基带 SoC，用专用硬件加速 Layer 1 等计算，以改善容量、功耗和尺寸。专用加速的意义在于：无线物理层包含 FFT、信道估计、矩阵运算、编解码等规则且高度并行的工作，通用 CPU 虽灵活，但在确定性时延和每瓦性能上未必最优。[O81][O85]

**分析判断。** RAN 平台价值来自硬件与软件长期协同：芯片性能决定可处理的载波、带宽、MIMO 层数和功耗边界；软件算法决定调度效率、无线性能和功能演进；射频与天线决定这些数字能力能否转化为真实覆盖。

### 4.5 Cloud RAN、Open RAN、anyRAN 和 AI RAN 不是同义词

| 概念 | 它改变了什么 | 不代表什么 |
|---|---|---|
| Cloud RAN | 把部分基带功能做成云原生软件，运行于通用/加速计算平台并支持池化 | 不自动意味着接口开放或任意厂商可互换 |
| Open RAN | 通过开放、标准化接口降低组件之间的专有耦合 | 不自动保证更低成本、更高性能或零集成工作 |
| anyRAN | Nokia 对 Cloud/Open RAN 组合的产品架构，支持 Nokia/第三方硬件和 O-RAN 接口 | 不是所有 RAN 功能都无条件运行在任何硬件上 |
| AI RAN | AI 与无线接入网络在算法、算力或业务层发生结合的总称 | 不是单一标准、单一设备或已经成熟统一的商业模式 |

Nokia 官网将 anyRAN 描述为支持 Cloud RAN、Open RAN 和 Cloud AI-RAN，可在 Nokia 或第三方硬件上部署并使用 O-RAN 接口。实际部署仍需逐项验证加速卡、服务器、实时内核、接口版本、RU 兼容、性能和责任边界。[O86]

### 4.6 AI RAN 的三种不同价值主张

行业常把 AI RAN 拆为三个方向。三者共享名称，但客户、收入方式和技术风险并不相同。

#### 4.6.1 AI for RAN：用 AI 优化无线网络

这是最接近现有 RAN 运维的路径。模型可以根据流量、信道、告警和能耗预测需求，优化参数、波束、邻区、节能和故障处理。

```text
网络遥测 → 特征/模型 → 建议或策略 → RAN 参数变更
        ↑                                ↓
        └────────── 结果反馈与闭环 ───────┘
```

真正难点不只是模型精度，而是安全闭环：错误动作是否可回滚，模型在不同城市和频段是否泛化，优化一个 KPI 是否伤害另一个 KPI，监管与客户是否允许自动执行。MantaRay SMO 提供跨传统/开放 RAN 的管理编排和 rApps 载体；AutoPilot 用 AI 和闭环策略处理拥塞、节能和性能问题。官网提到 TM Forum Level 4，并披露一个高负载案例 cell utilization 改善 30%，不可外推为全网普遍结果。[O88][O89]

#### 4.6.2 AI and RAN：AI 与 RAN 共享边缘算力

基站或电信边缘的计算平台白天/忙时运行 RAN，空闲资源运行推理、视频分析或其他边缘 AI 工作负载，希望提高硬件利用率。它需要资源隔离、实时调度、故障域和商业计费都成立。RAN 的确定性任务不能因 AI 作业抢占而失去时限，因此“共享 GPU”不是简单虚拟化问题。

#### 4.6.3 AI on RAN：利用网络边缘向终端提供 AI 服务

这一方向把运营商站点、边缘云和网络能力作为 AI 推理的分发位置，强调低时延、数据本地性和广覆盖。它的价值依赖可用应用、开发者生态、边缘部署密度、算力成本以及运营商能否收费；不应仅凭技术可行性推导大规模收入。

### 4.7 Nokia AI RAN 产品栈逐层拆解

| 产品层 | Nokia 产品 | 在 AI RAN 中的作用 | 核心约束 |
|---|---|---|---|
| 射频/天线 | Doksuri、Osprey、Habrok、Kolibri、Shikra | 提供真实无线覆盖、容量和波束，是 AI 策略最终作用的物理对象 | 频段、功放效率、校准、重量、散热和站址 |
| 专用基带 | AirScale + ReefShark | 以确定性时延执行传统/5G-Advanced 基带工作负载 | 每瓦容量、软件成熟度、载波与 MIMO 能力 |
| 云化基带 | anyRAN / Cloud RAN | 将部分基带软件放到云平台，连接通用 CPU/加速器和开放接口 | 实时性、前传、硬件适配、集成责任 |
| 管理编排 | MantaRay SMO | 管理跨厂商/跨架构 RAN 生命周期，承载 rApps | 数据模型、接口一致性、现网覆盖 |
| AI 闭环 | MantaRay AutoPilot | 从遥测形成优化策略并执行拥塞、节能和性能闭环 | 模型可信度、回滚、安全和跨场景泛化 |
| 跨域连接 | 7730/7750、NSP、1830 | 为前传/中传/回传和边缘云提供 IP/光连接与编排 | 同步、时延、可靠性、端到端可观测性 |

这张表揭示 Nokia 相对单一 AI 芯片厂商的结构性位置：Nokia 控制或参与从无线物理层、基带软件到传输和运维的多层接口。但“层多”同时意味着集成成本、产品复杂度和组织执行风险更高，并不自动等于更高利润率。

### 4.8 AI RAN 最容易被高估的地方

1. **把 AI 优化案例当作普遍收益**：单小区或特定高负载网络的改善不能直接外推。
2. **把共享算力当作无成本增量收入**：服务器、加速器、电力、散热、站点和软件隔离都有成本。
3. **忽略 RAN 实时性**：通用 AI 计算可以等待，HARQ、调度和物理层处理存在严格时限。
4. **把开放接口等同于即插即用**：接口合规不等于性能、运维和责任边界已完成集成。
5. **把边缘位置等同于客户需求**：只有应用愿意为时延、主权或网络能力付费，边缘算力才形成商业闭环。

### 4.9 AI RAN 的真正壁垒与验证点

**分析判断。** Nokia 的潜在优势不是独立训练基础模型，而是把 AI 能力放进可运营的无线闭环，并利用既有 RAN、传输和运营商关系交付。壁垒可能来自无线数据、领域模型、实时控制、安全回滚、跨代现网兼容和大规模部署经验。

后续应验证：Cloud AI-RAN 的真实商用客户和部署规模、共享算力利用率、相对专用 AirScale 的 TCO/能耗、第三方 RU/服务器互操作、MantaRay rApps 生态，以及 AI 功能最终按软件许可、订阅、算力分成还是设备升级收费。

## 五、三张网如何形成 Nokia 的系统级产品组合

### 5.1 Optical 与 IP：一个决定光怎么走，一个决定包怎么走

IP 层看到的是拓扑、地址、标签、队列和业务 SLA；光层看到的是波长、频谱、功率、色散和链路余量。IP 路由可能认为 A 到 B 有路径，但若底层没有可用波长或光信噪比不足，业务仍无法开通。反过来，光层有空闲容量，也不代表 IP 层会自动把流量送过去。

NSP、WaveSuite/Transcend 等跨层软件的价值，是把两套约束连接起来：

```text
业务意图：A 到 B 建立 400G，满足保护与时延要求
        ↓
IP 层：选择路由、标签、QoS 和保护策略
        ↓
光层：选择端口、波长、ROADM 路径和功率方案
        ↓
设备配置 + 验证 + 遥测
        ↓
故障时跨层重路由或重建业务
```

这也是 Nokia 同时拥有 IP 与 Optical 的战略意义所在，但能否转化为商业优势取决于客户是否采购一体化方案，以及跨层软件是否真的减少运营复杂度。

### 5.2 RAN 与 IP/Optical：无线容量最终必须被传出去

Massive MIMO 提高空口容量后，前传、中传和回传也需要同步扩容。低时延基带拆分要求更严格的同步和抖动；集中式基带需要可靠高容量连接；边缘 AI 又增加数据中心和 DCI 流量。因此 RAN 升级并非只有天线和基带订单，也可能拉动 7730/7750、光传输和 NSP 等跨域需求。

但这种协同不是机械的一比一绑定。运营商可能选择不同厂商的 RAN、路由和光设备，多厂商互操作是常态。Nokia 的机会来自组合交付和统一运维，风险则是客户主动拆分供应商以保持议价和技术独立。

### 5.3 面向 AI 客户的三类互联半径

| 半径 | 典型距离与场景 | Nokia 相关产品 | 主要技术矛盾 |
|---|---|---|---|
| scale-out：集群内部 | 机架间、数据中心内部 | 7220/7250 IXR、SR Linux/EDA、ICE-D | 带宽密度、尾时延、拥塞、每比特功耗 |
| scale-across：园区/DCI | 楼宇、园区到城域 | 7750 SR、ICE-X、1830 GX/PSI-M、FlexILS | 相干模块功耗、光层容量、自动化 |
| telecom edge | 基站、边缘云到核心/区域 DC | AirScale/anyRAN、7730/7750、1830、MantaRay/NSP | 无线实时性、边缘利用率、同步与端到端保障 |

**分析判断。** Nokia 的差异化不在单一半径绝对领先，而在产品组合横跨三类半径。研究上必须进一步确认这种广度带来的是交叉销售和工程复用，还是重叠产品、研发分散和较低资本效率。

## 七、风险、矛盾证据与尚未回答的问题

1. **产品上限不等于客户配置。** 官网容量、距离、节能和运营改善通常依赖特定条件；缺少统一第三方横评。
2. **芯片能力不等于系统份额。** PSE、FP5、ReefShark 的自研价值需通过客户采用、单位经济性和持续迭代证明。
3. **产品组合重叠。** Infinera 并入后，1830 与原 Infinera 多代系统并存，路线整合、EOS/EOL 和研发资源分配仍需跟踪。[H]
4. **开放与垂直整合存在张力。** Nokia 一方面强调开放多厂商，另一方面又希望通过芯片、设备和软件一体化获得差异化；客户会在便利与锁定之间权衡。
5. **AI 数据中心竞争不同于运营商市场。** Hyperscaler 的采购周期、软件生态、白盒接受度和成本结构与电信客户不同，运营商经验不能直接外推。
6. **AI RAN 商业模式尚未充分披露。** 官网证明产品方向存在，但不能据此确认大规模收入、利润率或算力利用率。
7. **光网络价格与单位经济性缺失。** 未披露模块/机框 ASP、BOM、良率和产品线毛利，无法从技术参数直接推导盈利弹性。

## 八、术语速查

| 术语 | 最简解释 |
|---|---|
| ADC / DAC | 模拟转数字 / 数字转模拟，是相干 DSP 与模拟光前端之间的桥梁 |
| DCI | Data Center Interconnect，数据中心之间的高速连接 |
| DSP | 对高速采样信号做均衡、恢复、FEC 等数字计算的处理器 |
| ECMP | 在多条等价路径间分担流量 |
| EVPN | 通过 BGP 分发二层/三层网络可达与多归属信息的控制平面 |
| FEC | 前向纠错，用冗余编码纠正传输错误，代价是开销和时延 |
| Leaf-spine | 数据中心两层 Clos fabric，依靠大量并行等价路径横向扩展 |
| MPLS | 通过标签转发和建立 VPN/流量工程路径的技术 |
| OTN | 面向光传输的数字封装、监控、纠错和交换体系 |
| PIC | 光子集成电路，把多个光学功能集成到芯片上 |
| QAM | 同时利用幅度与相位状态编码信息的调制方法 |
| ROADM | 可远程重构、按波长上下路或转向的光分插复用节点 |
| RRH/RU | 靠近天线的远端射频单元/无线单元 |
| Segment Routing | 用一组段指令表达网络路径意图 |
| SerDes | 芯片间高速串行收发接口 |
| SMO | O-RAN 语境中的服务管理与编排平台 |
| WDM | 用多个波长让一根光纤并行承载多条光通道 |
