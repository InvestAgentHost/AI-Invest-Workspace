# 公司深度投研人机交互规范

## 这份文件的作用

这是 Workspace 的通用人机协作规范，记录分析师与 AI 如何共同完成一次深度研究，以及研究完成后如何由 Agent 接续跟踪。它不是某一家公司的研究结论，也不替代 `AGENTS.md` 的文件安全规则、具体 skill 的专业方法或公司的研究上下文包。

本文件是交互范式的正式版本。若本文件与公司专属研究上下文冲突，以公司最新确认的边界和参数为准；若与 `AGENTS.md` 或用户当轮明确要求冲突，以后者为准。

## 一、默认协作角色

分析师负责研究问题、投资判断、重要假设和最终取舍。AI 负责资料定位、历史重整、计算、证据对照、草稿撰写、模型更新和一致性检查。AI 可以提出判断，但不能把未获采用的判断伪装成公司事实或已批准参数。

“深度研究完成”不是报告写完，而是形成一套可继续使用的研究包：原始资料、结构化底稿、研究上下文、已采用参数、决策记录、报告和验证记录能够互相定位。

## 二、启动研究时的交互顺序

### 1. 先恢复上下文

AI 先检查公司身份、交易市场、财年、最新实际期、现有报告、Excel 底稿、来源台账、估值接管记录和未解决问题。若存在用户上传的 Word 报告，先把它作为研究上下文阅读：恢复研究主线、章节结论、分析师判断、已采用假设和证据缺口。

Word 报告用于恢复判断和研究脉络，不能替代最新 SEC/公司披露作为历史实际数据来源。报告中的数字若要进入实际数据表，必须回到原始披露或明确标为“报告中已有的分析计算”。

### 2. 再给研究计划

计划必须说明：研究目标、资料边界、分析阶段、预计产物、已知缺口、需要分析师拍板的事项。计划应按公司经济链设计，不预设门店、加盟、用户、市场份额或其他特定商业模式。

只有身份、范围、重大估值边界、外部写入或其他会改变任务方向的事项需要确认。常规的检索、计算、只读检查和已授权的工作不重复询问。

### 3. 边做边交付可验证结果

每个研究模块采用以下顺序：

```text
先给结论
→ 展示支撑结论所需的完整历史或近期数据
→ 解释经济机制
→ 区分事实、计算、判断、假设和缺口
→ 指出投资含义与需要跟踪的变量
```

不要把数据逐行堆成结论，也不要只给挑选后的年份。用户要求完整历史时，应展示完整年度和必要的连续季度；用户要求精炼时，只保留支撑判断的关键数据和逻辑。

## 三、章节写作与分析纪律

- 章节开头用一至两段说明长期模式、近期变化及两者的连接，不把开头写成数据目录。
- 每个表格后必须解释数据意味着什么；表格用于紧凑结构化信息，长期论证用段落。
- 任何指标变化都要回到公司自身经营机制和披露解释；不能把同一套驱动因素套给不同公司。
- 长期与近期并列：长期回答商业模式如何形成，近期回答增长/下滑目前由什么构成，以及长期逻辑是否仍然成立。
- 经营分析、基本面、行业分析和估值各自提供增量信息；已经证明的结论可以引用，但不在后续章节机械重述。
- 信源至少区分 SEC/公司披露、公司管理层主张、业绩会或投资者日纪要、第三方资料、分析计算和研究判断。未披露就写 `unavailable`，不以零或估计替代。
- 参考公司只提供组织方式和审核标准，不能带入事实、参数、合同期限、商业模式或结论。

### 研究写作以逻辑为主线

分析师于 2026-10-15 确认以下标准，适用于投研报告及对话中交付的章节正文：

> 重要的是逻辑，数据是佐证。抓住主要矛盾、核心逻辑，把重要性高的细节点出来适当讲解，而不是堆砌数据。

- 写作前先明确本节要解释的主要问题和核心判断，正文围绕影响经营与投资判断的因果关系展开。核心判断必须由官方披露和可追溯计算支持，不为叙事强行归因。
- 区分证据覆盖与叙述篇幅：按研究范围保留必要的完整历史和结构数据，但正文按主要驱动因素、结构变化和关键转折组织，不逐年复述表格，也不把每个报表项目同等展开。只有时间顺序本身影响因果解释时，才按阶段叙述。
- 根据影响规模、增量贡献、持续性，以及是否改变业务结构、比较基础或投资判断，安排细节的篇幅。重大事项应讲清其性质、作用机制及对核心结论的影响；次要项目可合并、简述或留在底稿，不因资料可得就逐项罗列。
- 金额暂小但改变趋势判断、业务边界或风险认识的事项，以及反向证据、口径差异和重大不确定性，仍须交代。精简正文不能削弱证据完整性，也不能跳过必要逻辑。
- 表格承担规模、增速和结构的对照，正文解释变化为何发生、意味着什么。避免连续重复表中数字；选择能证明核心判断的数据，并明确事实、计算与判断之间的关系。
- 按经营问题安排段落与章节，关联性强的内容连续分析；不为每个年份、指标或一次性项目另设小节。交付前检查读者能否抓住本节核心判断及其证据链，并删除不影响理解和判断的枝节。

### 经营分析以官方披露与底稿为主线

分析师于 2026-10-14 确认以下标准：

> 底稿数据来自10K官方披露，这是最重要的了解公司经营的窗口，也是你进行投研分析的逻辑主线。

- 从年报及其形成的 Excel 底稿展开经营分析。先读懂指标定义、统计范围、单位、比较基础，以及公司通过这些数据解释的经营问题；结合脚注和管理层讨论理解披露用意，不臆测公司动机。
- 对用户要求完成的经营模块，一次性覆盖底稿中相关的总量、结构、分部或地域、产品、历史与近期数据，以及影响可比性的调整。按公司的实际披露选择维度，不停在全球总量或少数亮点，也不要求用户逐项提醒遗漏。
- 分析顺序为：确认口径和范围，展示相关数据，解释长期走势与近期变化，拆解内部差异，再形成经营判断。结论的范围不得超过数据的统计范围。
- 对不同口径的指标，先分别完成各自的数据与经营分析，再解释两者的联系。不能以指标之间的比较代替任何一个指标本身的完整分析。
- 年报官方披露是事实依据，底稿是组织和计算载体。季度及品类补充使用对应官方公告；会议纪要、官网和第三方资料用于解释、补充或检验数据所揭示的问题，不取代年报主线。发生冲突时优先核对正式披露并保留差异。
- 以经营全貌安排细节的篇幅。品牌案例、渠道动作和管理层表述必须说明其与总量或结构变化的联系；没有权重、同口径数据或明确解释时，不将个别案例推算为整体增长贡献。
- 每个分析环节都交代所用数据、推导关系和判断边界。避免跳过必要的统计范围或比较基础，既不陷入孤立细节，也不脱离官方数据自由推演。

### 收入与利润表格的默认展示要求

分析师于 2026-10-15 确认以下要求，适用于对话正文、研究报告及 Excel 展示表中的收入与利润分析：

- 默认采用“金额（同比）”的紧凑展示：同一指标的金额与同比放在同一单元格，指标名写“合并收入（同比）”“营业利润（同比）”等。例如 `47,941（+1.9%）`、`36,212（−13.5%）`；除用户另有要求或分析确有需要外，不为金额与同比各占独立行或列。
- 按分析师于2026-10-26确认的偏好，财务与经营时序表默认以财年或季度作为列（columns），指标作为行索引（index），首列列示指标或业务名称，期间从左到右按时间顺序排列。这是默认布局，可根据表格用途、数据量及阅读空间调整，以清晰、美观、便于比较为准。例如，单期分部对比可以业务为行、收入与增速等指标为列，不为遵守默认方向而机械拉成长单列表；过宽的历史表可合理分区。年度、单季度和年初至今数据须明确区分期间；连续季度使用 `FY2026Q1` 等完整期间标签。数值右对齐，金额使用千位分隔符，单位在表前或表下注明。同比默认保留一位小数，正值带 `+`，负值带 `−`；起始期无可比数据时写作 `41,863（—）` 并说明原因。收入占比、利润率和增长贡献等作为独立指标，按布局选择行或列，明确分母，不与同比混用。此偏好适用于对话、研究报告及Excel展示层；概念对照表按内容组织。
- 收入与利润规模、结构表必须同时列示金额和各项同比增速。合并收入、各地区、各分部、各业务类别，以及地域与业务交叉分类中的每项收入，都应有各自的同比，不能只给合并收入同比；表中列示的毛利、营业利润、净利润等金额同样适用。结构分析同时列示相关占比，并明确占比的分母；占比不能替代同比。
- 上年同期金额为正时，同比按“本期金额 ÷ 上年同期金额 − 1”计算，年度、季度、半年度分别与上年相同期间比较，使用相同业务分类和统计范围。存在重述或分类调整时，优先使用最新披露的比较数并注明差异。根据报表收入计算的同比，应与公司披露的有机增长、固定汇率增长等口径区分，并注明来源及计算属性。
- 起始年度缺少上年同口径数据、比较数不可得或上年金额为零时，注明无法计算的原因，不以零增速或估计值替代。利润上年为负或发生盈亏转换时，优先用“扭亏”“转亏”“亏损收窄／扩大”等说明，避免机械计算产生误导。交付前逐项检查金额、同比及结构占比，不等待用户逐项提醒。
- Excel 底稿的金额与同比仍保留为可计算的独立数值或公式；紧凑格式用于展示层，不为合并显示而将底层数值、公式改成文本。

### 正文金额采用中文习惯单位

分析师于 2026-10-15 确认以下要求，适用于对话与研究报告的文本叙述：

- 金额按数量级采用中文读者习惯的“万”“亿”等单位，避免直接沿用源表的“百万美元”等表述。例如，`761百万美元`写作`7.61亿美元`，`60百万美元`可写作`6000万美元`或`0.6亿美元`，以通顺易读为准。
- 单位换算保留原币种和数值含义，不因改写单位而损失有意义的精度；同一段落中的比较尽量使用一致单位。
- 表格保留原始披露或底稿的单位、数值尺度及数字，在表前或表下注明单位；不因正文改用“万／亿”而同步换算表格数字。

### 资产负债表章节的分析与展示

分析师于 2026-10-16 确认：资产负债表应解释历史资本配置如何形成当前报表，正文选择重点科目，并在本节内衔接运营资本、周转效率和资产结构；完整历史数据不要求逐年叙述。资产结构默认用一张金额堆积图，柱顶标总资产、各区块标占比，细小区块用引线，不重复提供功能相同的百分比图。

具体分析步骤、口径、表图要求及完成标准由 [company-deep-investment-research 的资产负债表章节规范](../.github/skills/company-deep-investment-research/references/financial-reconstruction.md#6-资产负债表章节分析与写作) 统一维护。执行资产负债表任务时先读该规范，不以本段摘要代替专业规则。

资本回报分析使用分析师于2026-10-16确认的“经营IC／经营ROIC”口径，定义及核对要求统一维护于主skill的[经营IC章节](../.github/skills/company-deep-investment-research/references/financial-reconstruction.md#41-经营ic与经营roic的统一口径)。已有底稿公式不同时须先重算，不能沿用旧数值只修改名称。

## 四、参数推导的拍板机制

对关键参数使用“建议—证据—采用值—影响”的短循环：

1. AI 列出历史锚点、管理层指引、反向证据和建议区间；
2. AI 说明该参数影响哪些下游计算；
3. 分析师给出采用值、修改值或暂不确定；
4. AI 将决定写入决策记录，并让 Excel 通过链接自动重算；
5. AI 汇报结果变化和仍未解决的问题。

未拍板的低/高情景可以保持空白，不能当作零。用户手动改 Excel 后，AI 应先识别差异并登记为 workbook-origin 决策，不能用旧结构化参数静默覆盖。

## 五、估值阶段的固定交互

估值使用 `valuation-binding-methodology`。先完成当前未结束财年的剩余季度，再得到完整财年基期，随后推导未来年度；不能先拍一个净利润 CAGR 再反推经营数据。

`Valuation Driver Build` 中预测在左，同指标历史数值在右；历史数据必须是可读的数字或明确缺口，不能只放来源链接。用户确认经营驱动后，AI 再更新利润、现金、股数、EPS 和估值。

每次估值交付都说明：估值日期、基期、方法、采用参数、现金用途边界、退出倍数依据、敏感性、结果和未决问题。直接退出 PE、分红和净缩股的具体公式以估值 skill 为准，不在本文件复制第二套计算定义。

## 六、文件与产物交互

- 用户上传资料可以直接放在 `research/companies/<market>/<company-id>/data/`，研究期间视为收件区。
- 外部原始资料不覆盖；个人 Word 默认不直接修改，章节草稿在对话中交付供用户粘贴。
- Excel 修改遵循受控更新：保留用户手动输入、未涉及工作表、公式、格式和原生功能；不能从过期中间文件整本覆盖。
- 研究完成时，AI 列出新增资料的归档计划和目标路径，询问用户后再归档。未确认不移动、不删除、不清理收件区。
- 每次跟踪保留旧预测、实际与预测差异、输入变化、估值变化归因和新快照。

## 七、财报跟踪模式

用户可以用一句话触发，例如“麦当劳发布了 2026Q3 财报，请更新底稿和估值”。AI 按以下顺序执行：

```text
读取 context pack 和上一版快照
→ 获取并归档新披露
→ 更新实际季度
→ 保留并对照旧预测
→ 更新剩余季度和全年基期
→ 复核未来年度驱动
→ 重算利润、现金、股数、EPS、估值
→ 独立校验和版面检查
→ 输出变化归因、未决问题和新快照
```

普通季度偏差直接更新；若业务边界、利润机制、资本强度、融资约束、治理风险或长期需求前提发生实质变化，先标记“投资逻辑重审”，不能无条件沿用旧参数。

## 八、交互节奏

- 大任务先给计划，随后持续推进独立工作，不停在“可以开始吗”。
- 需要用户决定时，一次集中列出真正改变结果的问题，避免逐条打断。
- 用户已明确采用的口径、参数或交付方式在后续不重复询问。
- 发现数据、公式或路径错误时，先说明错误影响，再修复并重新验证。
- 用户只问一个概念时先直接回答；用户要完整研究时再展开数据和推导。
- 最终回复报告完成内容、验证结果、重要限制和文件路径；不把内部工具日志当作研究结论。

## 九、完成判定

一次深度研究只有在以下条件同时满足时才算完成：

- 事实、计算、判断、假设和缺口已分层；
- 关键历史数据和近期数据可追溯；
- 报告、Excel 和估值参数一致；
- 重要参数有分析师采用记录；
- 结果通过计算、来源和版面检查；
- 原始资料、报告、底稿和快照有明确归档位置；
- 已列出后续跟踪指标和投资逻辑重审触发条件。

## 十、官网快照交付

官网快照完成发布后，只把最终交付版的公司手册、战略与发展、重要信息三份 Markdown 镜像到 `research/companies/<market>/<company-id>/outputs/official-site-snapshot-<YYYYMMDD>/`；原始页面、JSONL、索引和完整溯源仍保留在 `sources/companies/<market>/<company-id>/`。在公司的 release review 或等效台账中记录镜像路径。该规则适用于所有公司，不因单一公司的资料结构改变。
